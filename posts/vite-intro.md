## Vite 为什么这么快？

Vite 的核心优势可以用一句话概括：**在开发环境利用浏览器原生 ESM，在生产环境使用 Rollup 打包**。

## 核心架构

```
┌──────────────────────────────────────────────┐
│                  浏览器                      │
└──────────────────────────────────────────────┘
                    │ HTTP
                    ▼
┌──────────────────────────────────────────────┐
│              Vite Dev Server                 │
│  ┌─────────────┐   ┌─────────────────────┐  │
│  │  Koa 服务器  │   │   Middleware        │  │
│  └─────────────┘   │   - esbuild 预构建  │  │
│                     │   - 模块转译        │  │
│                     │   - HMR             │  │
│                     └─────────────────────┘  │
└──────────────────────────────────────────────┘
```

## esbuild 的作用

- 使用 Go 编写，比 JS 工具快 10~100 倍
- 负责 **预构建**（将 CommonJS 依赖转为 ESM）
- 负责代码转译（TS → JS, JSX → JS）

## 生产构建：Rollup

生产环境仍然需要打包，因为：

- ESM 在浏览器中存在大量 HTTP 请求，影响首屏性能
- 需要 Tree-shaking
- 需要压缩优化

Vite 选择 Rollup 作为打包器，因为 Rollup 的插件生态最丰富。

## 小结

Vite 的快不是一个单点技术，而是 **浏览器 ESM + esbuild + Rollup** 的巧妙组合。理解了这一点，再看 Vite 的配置和插件就会轻车熟路。
